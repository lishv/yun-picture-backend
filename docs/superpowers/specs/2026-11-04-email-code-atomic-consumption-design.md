# 邮箱验证码原子消费设计

## 目标

将邮箱验证码的读取、校验和删除合并为一个 Redis 原子操作，防止两个并发请求同时使用同一个验证码。

## 现状

注册和重置密码当前先调用 `verifyCode` 从 Redis 读取并比较验证码，完成数据库操作后再调用 `deleteCode`。两个请求可能在删除前同时读取到相同验证码并通过校验。

## 设计

保留现有 `EmailManager.verifyCode` 调用入口，内部改用 Redis Lua 脚本：

1. 读取验证码；不存在时返回 `-1`。
2. 与用户输入按字符串比较；不匹配时返回 `0`，不删除验证码。
3. 匹配时删除验证码并返回 `1`。

Lua 脚本由 Redis 原子执行。注册和重置密码不再在数据库操作后重复调用 `deleteCode`，并删除不再使用的 `deleteCode` 方法。

Redis 与 MySQL 不组成同一个事务。验证码校验成功后立即被消费；如果后续数据库操作失败，用户需要重新获取验证码。本次以一次性验证码不可并发复用为优先目标。

## 范围

- 修改 `EmailManager.verifyCode`。
- 修改邮箱注册和重置密码调用链。
- 不修改验证码发送、有效期和发送冷却逻辑。
- 不新增配置。

## 验证

- 正确验证码：Lua 返回 `1`，校验通过且验证码已删除。
- 错误验证码：Lua 返回 `0`，提示验证码错误且不删除。
- 不存在或过期：Lua 返回 `-1`，提示验证码已过期。
- Java 17 编译及相关测试通过。
