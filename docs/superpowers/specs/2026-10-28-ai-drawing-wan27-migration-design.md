# AI 绘图迁移至 Wan2.7 设计

## 背景

现有“AI 扩图”功能调用阿里云百炼 `image-out-painting` 模型。该模型已经下线，创建任务时返回 `Model not exist`，功能无法继续使用。

本次将功能调整为“AI 绘图”：用户输入提示词，系统同时提交当前图片和提示词，使用 `wan2.7-image` 基于当前图片进行再创作。

## 目标

- 将阿里云模型迁移为 `wan2.7-image`。
- 用户能够输入提示词，基于当前图片生成一张新图片。
- 用户界面统一使用“AI绘图”名称。
- 继续使用现有异步任务提交、前端轮询、结果预览和应用结果流程。
- 保留现有 API Key、业务空间域名和环境配置结构。
- 以最小改动完成迁移，不增加回调函数和额外任务存储。

## 非目标

- 不支持纯文本生成图片，当前图片始终作为参考图提交。
- 不支持一次生成多张图片或连续组图。
- 不重命名现有 `OutPainting` Java 类、前端组件文件和 `/out_painting` 接口路径。
- 不引入或升级阿里云 DashScope Java SDK。
- 不增加自动重试、任务持久化或新的消息队列流程。

## 方案选择

继续使用项目现有的 HTTP 异步调用方式，而不是改用 DashScope SDK：

1. 创建任务仍通过 HTTP 请求并携带 `X-DashScope-Async: enable`。
2. 前端继续每 3 秒查询一次任务状态。
3. 查询接口仍使用 `/api/v1/tasks/{taskId}`。
4. 后端适配 Wan2.7 的请求和响应结构，对前端继续提供 `outputImageUrl`。

这样能够保留现有调用链，不引入同步阻塞或回调处理。

## 配置

在 `application-local.yml` 和 `application-prod.yml` 的现有 `aliYunAi` 配置下分别增加：

```yaml
aliYunAi:
  model: wan2.7-image
```

模型名不放入公共 YAML。后端通过 `${aliYunAi.model}` 读取模型名，原有 `apiKey` 和 `apiHost` 保持不变。

## 后端设计

### 业务接口

创建任务的前端请求由以下内容组成：

```json
{
  "pictureId": 123,
  "prompt": "将背景改为夜晚的城市，保持人物外观不变"
}
```

后端根据 `pictureId` 查询图片，使用数据库中的图片 URL 作为参考图。前端不直接提交参考图 URL。

### 内置提示词

后端固定以下提示词前缀，前端只提交用户要求：

```text
你正在执行基于参考图片的定向图像编辑任务。必须遵循以下规则：
1. 除非用户明确要求，否则保留原图主体身份、核心外观特征和主要构图。
2. 只修改用户明确要求的内容，不得擅自改变、删除或替换无关主体。
3. 未指定区域应尽量保持原样；新增或修改内容必须与原图的风格、色彩、光照、透视和清晰度自然融合。
4. 输出一张完整、清晰的图片，不要增加用户未要求的文字或水印。
用户要求：
```

提交阿里云前，将固定前缀和去除首尾空白后的用户提示词直接拼接。固定前缀只存在于后端，前端不展示、不保存，也不允许调用方覆盖。

为给固定前缀预留长度，用户提示词最大长度为 4800 个字符。前端限制输入长度，后端同时校验非空和最大长度。

### 阿里云请求

创建任务地址调整为：

```text
https://{apiHost}/api/v1/services/aigc/image-generation/generation
```

请求体固定为单图编辑、单图输出：

```json
{
  "model": "wan2.7-image",
  "input": {
    "messages": [
      {
        "role": "user",
        "content": [
          { "image": "当前图片URL" },
          { "text": "用户输入的提示词" }
        ]
      }
    ]
  },
  "parameters": {
    "size": "2K",
    "n": 1,
    "watermark": false
  }
}
```

创建任务成功后，继续向前端返回阿里云提供的 `taskId` 和任务状态。

### 任务结果适配

任务查询地址保持不变：

```text
https://{apiHost}/api/v1/tasks/{taskId}
```

Wan2.7 的生成图片位于：

```text
output.choices[0].message.content[0].image
```

后端读取第一项 `type=image` 的内容，将图片 URL 写入现有响应字段 `outputImageUrl`。前端因此可以继续使用当前结果预览和 URL 上传逻辑。

## 前端设计

- 页面入口、弹窗标题及消息提示中的“AI 扩图”统一改为“AI绘图”。
- 弹窗继续展示左侧当前图片、右侧生成结果。
- 增加必填的多行提示词输入框，最大长度为 4800 个字符。
- 提示词占位示例：`请描述你希望如何修改当前图片，例如：将背景改为夜晚的城市，保持人物外观不变。`
- 创建任务时提交 `pictureId` 和 `prompt`，不再提交 `xScale`、`yScale` 等旧扩图参数。
- 用户未输入提示词时不发起请求。
- 创建成功后继续每 3 秒轮询任务。
- 生成成功后展示图片，用户点击“应用结果”时继续沿用现有 URL 上传流程保存到 COS。

## 异常处理

- 前端和后端均校验提示词不能为空且不超过 4800 个字符。
- 创建任务失败时提示“AI绘图任务创建失败”。
- 轮询得到 `FAILED` 时停止轮询，并显示任务返回的失败信息。
- 任务状态为 `SUCCEEDED` 但没有图片 URL 时，停止轮询并提示“AI绘图未返回图片”。
- 不增加自动重试、回调或其他额外容错机制。

## 验证

- 后端测试 Wan2.7 请求体包含配置的模型名、当前图片 URL、用户提示词和固定生成参数。
- 后端测试提交给阿里云的提示词包含固定前缀，并以用户提示词结尾。
- 后端测试任务结果中的第一张图片能够转换为 `outputImageUrl`。
- 确认 local 和 prod 配置均包含 `aliYunAi.model`。
- 运行后端相关测试。
- 运行前端类型检查和构建。
- 自动测试不调用收费的阿里云接口；部署后使用一张图片进行人工验证。

## 最终数据流

```text
用户输入提示词
  -> 前端提交 pictureId + prompt
  -> 后端查询当前图片 URL
  -> 提交 Wan2.7 异步图像编辑任务
  -> 前端轮询任务状态
  -> 后端提取生成图片 URL
  -> 前端预览结果
  -> 用户应用结果并保存到 COS
```
